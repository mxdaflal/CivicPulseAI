The PostgreSQL suite checks signup metadata cannot select admin, role/profile escalation is denied, another citizen cannot enumerate reports or analyses, reference-only tracking fails, the correct capability returns a restricted projection, unassigned operators cannot view/update an incident, reviewers cannot erase audits, duplicate verification is prevented, assignment/progress/resolution are persisted atomically, meaningful resolution notes are required, anonymous private-table/evidence access is denied, and citizen-safe tracking/public statistics reflect the stored workflow.

The database fixture implements minimal Supabase auth/storage schema contracts and actual PostgreSQL grants/RLS. It does **not** verify Supabase Auth token verification, actual Storage HTTP downloads, signed URL expiry or Realtime transport delivery. `tests/supabase.integration.test.ts` covers those against a real local stack and refuses a remote target before creating data. The full Supabase image pull was stopped when its footprint exhausted this 32 GB environment; no installed stack is claimed.

A browser test initially exposed valid local POST requests being rejected because Next.js normalised the internal URL to localhost. The guard and auth redirects now use the public Host or an explicit canonical application origin; a regression test and the rerun browser suite passed.

Both required public Supabase variables remain absent. Consequently the application shows its configuration screen; a clean build is not a claim that reporting or authentication has been exercised against a hosted database. Add the actual development project values securely, apply/review the migration in staging, and run the configured browser, Auth/Storage/Realtime, access-control and demonstration checks before release. Migration, optional anonymous reporting and provider integration are release gates, not assumed successes.

GitHub native Git read access was verified. GitHub's API was denied by the active egress policy; an `api.github.com` addition is saved in the environment draft. Saving that draft does not apply the policy or create a pull request. Publication is a separate user action after setup and validation.
